# 0016 — 游戏术语统一 + 命运机制规则

**状态**：✅ 术语已实施；命运主动出牌规则设计定义，实现待定  
**日期**：2026-04-05

## 背景

原有 UI 标签（手牌/环境/场地）描述性不足，与游戏叙事脱节，也未区分己方/对方概念。同时需要明确对方（命运方）的出牌规则，以完善双方对弈框架。

## 决策

### 1. 术语统一

| 旧称 | 新称 | 位置 | 含义 |
|------|------|------|------|
| 对方手牌 | **命运** | Row 2（面朝下） | 对方持有的未知牌，代表生活中不可预知的力量 |
| 环境 | **事件** | Row 3（已翻开） | 本回合已触发的命运牌，代表已发生的事件 |
| 场地 | **应对** | Row 4 | 玩家打出的持续性应对策略牌 |
| 手牌 | **手牌** | Row 5 | 玩家当前持有的可用牌（不变）|

### 2. 命运方出牌规则

命运方（对方）每回合的行动逻辑：

```
回合结束 → 命运方从命运牌组抽牌到命运手牌
         → 将命运手牌全部打出，直到事件位满为止
         → 超出事件位上限的牌进入命运弃牌堆
```

- 命运手牌数量 = `fate_hand_size`（YAML 配置，默认等于 `env_per_turn`）
- 事件位上限 = `env_per_turn`（已有配置）
- 命运手牌对玩家不可见（面朝下显示数量）

**当前实现**：`envHand` 即命运手牌，每回合抽 `env_per_turn` 张，翻开即全部结算。与上述规则等价（抽几张打几张，事件位 = 抽牌数）。

**差异**：未来若 `fate_hand_size > env_per_turn`，命运方会"攒牌"，选择性打出至事件位满。这是更复杂的 AI 策略层，当前暂不实现。

### 3. 玩家策略牌对命运的干预

玩家可通过策略牌影响命运方的约束参数：

| 策略效果 | 机制变量 | 说明 |
|---------|---------|------|
| 减少事件位 | `env_per_turn` 临时 -N | 本回合/N回合内命运牌上限减少 |
| 减少命运手牌数 | `fate_hand_size` 临时 -N | 命运方每回合摸牌变少 |
| 封锁特定类型事件 | 条件过滤 | 某类事件本回合不触发 |
| 查看命运手牌 | 信息获取 | 临时揭示面朝下的命运牌 |

> 实现方式：卡牌 `effects` 支持 `target: game_param` 类型的 delta，在 `endTurn` 结算前读取修正值。具体实现待设计。

## 后果

- ✅ 术语贴合游戏叙事（"命运"/"事件"/"应对"比"环境"/"场地"更有代入感）
- ✅ 明确了双方框架：命运方 vs 玩家方，信息不对称是核心张力
- ✅ 为策略牌干预命运提供了设计空间，无需改变基础战斗循环
- ⚠️ `fate_hand_size > env_per_turn` 的命运 AI 策略层尚未实现，当前命运方是确定性的
- ⚠️ 策略牌影响 `game_param` 的 effect 类型需要新的 loader 和结算逻辑支持
