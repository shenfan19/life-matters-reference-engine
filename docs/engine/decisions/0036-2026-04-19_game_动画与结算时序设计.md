# 动画与结算时序设计（ADR）
**日期**：2026-04-19  
**状态**：已实现  
**涉及文件**：`game/src/components/CardGame.tsx`、`game/src/components/CardGame.css`、`game/src/core/newFormatLoader.ts`、`plugins/preprocessors/story_converter/backend.py`

---

## 核心命题

> **事件牌在回合开始时亮面展示，与出牌一同在点击"结束回合"时结算；结算后破碎消失，下一回合的新事件再滑入。**

游戏节奏改变为：**计划阶段（看到事件 → 打出应对）→ 结算阶段（点击结束 → 动画依次结算）→ 交接阶段（事件破碎 → 新事件滑入）**。

---

## 设计决策

### 1. 结算时序：Pending → Resolved → Shatter → Next

旧做法（已废弃）：事件牌在回合**开始**时结算，玩家还没出牌就已扣血，动画也在错误时机触发。

新做法：

| 阶段 | 状态 | 动画 |
|---|---|---|
| 回合开始 | 新事件牌以 `pending: true` 亮面出现 | `card-reveal-in`（从右滑入）|
| 计划阶段 | 玩家看见事件，决定出哪些应对牌 | 无 |
| 点击"结束回合" | 依次结算：驻场牌 → 被动环境 → 本回合事件 → 出牌 | `card-resolving`（Balatro 震动）|
| 结算完毕 | 事件牌状态改为 `triggered/missed`，随即破碎 | `card-shattering`（缩放+旋转+淡出）|
| 交接 | 下回合新事件滑入，`pending: true` | `card-reveal-in` |

`RevealedEnvCard` 的 `pending?: boolean` 字段是状态机的核心：`true` = 尚未结算的本回合事件，`false` = 已结算（或被动常驻）。

---

### 2. 被动牌（always_active）永不破碎

`isPassive: true` 的牌始终驻场，每回合参与震动结算但不进入破碎流程。两类牌在 `envRevealed` 中共存，由 `isPassive` 区分处理。

---

### 3. 动画时序常量（CSS + setTimeout 编排）

```
SHAKE_DUR  = 360ms   每张牌震动持续时间
SHAKE_GAP  = 80ms    震动之间的间隙
SHATTER_DUR= 280ms   破碎动画
SLIDE_LAG  = 120ms   破碎结束到新牌滑入的停顿
SLIDE_DUR  = 450ms   新牌滑入动画
```

shake 顺序：驻场牌（逐张）→ 被动事件（逐张）→ 本回合事件（逐张）→ 出牌（逐张）

每张牌震动时，该牌所影响的 **变量仪表也同步 `gauge-shaking`**，提示玩家哪个数值在变化。

---

### 4. Pending 状态的渲染差异

`pending: true` 的事件牌：
- `triggered={undefined}` — 不显示已触发/未触发样式
- `showMissed={false}` — 不显示"未触发"标记
- hover 效果显示**正向预览**（effects 原值），而非反向 counterfactual

结算后 `pending: false`：正常显示 triggered/missed 样式，动画结束后即破碎消失。

---

### 5. 区域标签语义更新

| 旧标签 | 新标签 | 说明 |
|---|---|---|
| 事件 | **本回合事件** | 明确这是"即将在本回合结算"的事件，非历史 |
| 应对 | **驻场** + **出牌** | 驻场（跨回合持续牌，仅在 `board.length > 0` 时显示）/ 出牌（本回合打出的应对区）|

---

### 6. 参考文献传播链

卡牌级别的 `references` 字段从 model YAML 出发，经全链路传播至游戏内 tooltip：

```
model YAML → backend.py (_to_new_card) → card YAML → newFormatLoader.ts (toPlayerCard / toEnvCard) → PlayerCard / EnvCard 接口 → GameCard tooltip hover
```

converter 将 `metadata.references` 附加到每张生成的牌（env 和 player），确保游戏内展示来源可溯。

---

### 7. 事件牌组计数

`envHand`（旧的面朝下缓冲区）废弃，初始化即将事件牌 `pending` 放入 `envRevealed`，右侧牌堆计数改为 `envEventDeck.length`（仅剩余未抽出的牌），不再叠加 `envHand.length`。

---

## 弃用方案

**方案 A（原始实现）**：事件牌保留 face-down 在 `envHand`，回合开始翻面并立即结算 → 玩家看不到事件就被扣血，反馈断层，已废弃。

**方案 B**：事件牌翻面后在同一帧结算，仅靠动画延迟掩盖时序错误 → 逻辑不正确，新事件立即参与当帧震动，已废弃。
