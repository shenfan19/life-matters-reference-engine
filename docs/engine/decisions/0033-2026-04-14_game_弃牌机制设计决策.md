## 核心结论

弃牌是**第四层命运叙事动作**，与出牌同等地位——都是主动选择、都可撤回、回合结束统一结算。

弃牌不是自由的：**仅当手牌超出上限时才允许弃牌**，体现命运压迫下的强制取舍，而非随意丢弃。

## 完整交互矩阵（2026-04-15 最终版）

### hand_size 语义（关键）

**`hand_size` 是回合末上限，不是即时上限。**

- 回合中：每回合自由抽取 `draw_per_turn` 张，不受当前手牌数限制，手牌可以超过 `hand_size`
- 回合末：手牌必须 ≤ `hand_size`，否则禁止点击"结束回合"，必须先弃至上限以内
- "弃牌→抽牌让路"的旧设计已废弃：抽牌不再受 `space` 约束

### 弃牌前置约束

```
handOverflow = regHand.length > story.game.hand_size
```
（regHand 排除永久牌，stagedDiscards 已移出 hand，不计入）

- `handOverflow = false` → 所有弃牌路径全部禁用
- `handOverflow = true`  → 开放以下弃牌路径；"结束回合"按钮同时变红并锁定

### 区域拖拽矩阵

| 拖拽来源 \ 放置目标 | 出牌区（play zone） | 弃牌区（discard zone） | 手牌区（hand zone） |
|---|---|---|---|
| **手牌** | ✅ 出牌（需行动点）| ✅ 弃牌（仅 overflow）| — |
| **出牌区已出牌** | — | ✅ 转入弃牌（自由，重算 gs）| ✅ 撤回手牌（自由）|
| **弃牌区暂存牌** | ✅ 转入出牌（需行动点，重算 gs）| — | ✅ 撤回手牌（自由）|

> **出牌区→弃牌区** 不受 overflow 约束：该牌不在手牌中，不属于"弃手牌"操作。

### 手牌区交互方式（三条路径）

| 方式 | 触发 | 约束 |
|---|---|---|
| 左键单击 | 出牌（消耗行动点） | `playsLeft > 0` |
| 右键单击 | 弃牌（进入暂存区）| `handOverflow = true` 且非永久牌 |
| 拖拽到弃牌区 | 弃牌（进入暂存区）| `handOverflow = true` 且非永久牌 |

### 其他撤回路径（点击）

- 出牌区已出牌 → 点击（↩）= 撤回手牌（`recallCard`）
- 弃牌区暂存牌 → 点击（↩）= 撤回手牌（`recallDiscard`）

### 回合结算

- `stagedDiscards` → `playerDiscard`（统一在 endTurn 处理，不可撤）
- 所有路径共用同一结算入口，无分支

## 实现细节

### 状态变量

| 状态 | 类型 | 用途 |
|---|---|---|
| `stagedDiscards` | `PlayerCard[]` | 本回合已暂存待弃的牌 |
| `dragOverDiscard` | `boolean` | 弃牌区高亮（拖拽悬停中）|
| `dragOverPlay` | `boolean` | 出牌区高亮（拖拽悬停中）|
| `dragOverHand` | `boolean` | 手牌区高亮（拖拽悬停中）|
| `dragSource` | `'hand'\|'played'\|'discard'\|null` | 当前拖拽来源，驱动视觉提示 |

### 原子操作函数

| 函数 | 作用 |
|---|---|
| `stageDiscard(card)` | 手牌 → 弃牌暂存（从 hand 移除，加入 stagedDiscards） |
| `recallDiscard(idx)` | 弃牌暂存 → 手牌 |
| `recallCard(idx)` | 出牌区 → 手牌（重算 gs） |
| `movePlayedToDiscard(cardId)` | 出牌区 → 弃牌暂存（重算 gs，+1 playsLeft） |
| `moveDiscardToPlayed(cardId)` | 弃牌暂存 → 出牌区（重算 gs，-1 playsLeft，需有空位）|

### DataTransfer 载荷

```
dataTransfer.setData('cardId',     card.id)
dataTransfer.setData('dragSource', 'hand' | 'played' | 'discard')
```

### 技术实现：HTML5 Drag & Drop API

- `GameCard` 接受 `draggable?`, `onDragStart?`, `onDragEnd?` props
- `cursor: grab` 当卡牌可拖拽时
- 弃牌区、出牌区、手牌区均为独立 drop target div，绑定 `onDragOver/Enter/Leave/Drop`
- `onDragEnd` 统一清理所有悬停状态（防止 drop 在非目标区导致残影）
- drop handler 通过 `dataTransfer.getData('dragSource')` 区分处理逻辑

### 视觉设计

| 区域 | 空状态 | 拖拽悬停 |
|---|---|---|
| 出牌区 | 黄色虚线槽（`#faad14`）| 黄色边框高亮 + 背景淡入 |
| 弃牌区 | 透明（`2px dashed transparent`）| 灰色虚线（`#8c8c8c`）+ 背景淡入 |
| 手牌区 | 无 | 蓝色边框高亮（`#1677ff`）+ 背景淡入 |
| 弃牌暂存牌 | 55% 透明度 + 45% 去饱和 | — |
| "放弃"标签 | 30% 透明灰 | 实色灰（拖拽进入时加深）|

### 日志语义

- 出牌：`打出 [xxx]`，绿色
- 放弃：`放弃了 [xxx]`，中性灰（非负面，体现叙事中性）

### 弃牌与抽牌的关系

- 抽牌不再受 `space` 约束——`hand_size` 是回合末限，回合中手牌可超限
- 每回合固定抽取 `min(draw_per_turn, deck.length)` 张
- 溢出由玩家主动弃牌解决（拖拽或右键），否则"结束回合"按钮锁定
- 弃牌暂存仍在回合末进入 playerDiscard，不影响下回合抽牌逻辑
