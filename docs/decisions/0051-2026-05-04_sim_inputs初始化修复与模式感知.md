# ADR 0051 — InputEvents 初始化修复、模式感知显示、isLocked 恢复、测试模型重构

**日期**：2026-05-04  
**状态**：已实施

---

## 背景

本 ADR 记录 2026-05-04 第二批修改，解决以下问题：

1. **inputs 不显示**：加载测试模型后，inputs 面板为空。根因：`skipInputInitRef` 在首次加载任意模型时跳过初始化，导致旧模型的 inputEvents（来自 localStorage）继续显示，新模型的 optimizer.inputs 标志不被应用。
2. **optimizer.inputs 标志未应用**：`freshInputInit` 门控导致 optimizer.inputs 的 `optimizeValue`/`valueBounds` 只在"全新初始化"时才应用，恢复场景下不应用。
3. **opt 模式按钮行为**：run 按钮在 opt 模式下不要求 isLocked，与产品期望不符（安全锁应两种模式一致）。
4. **sim/opt 模式 inputs 显示差异**：切换模式时 inputs 面板应展示不同内容：opt 模式只显示 optimizer.inputs 定义的决策变量，sim 模式显示所有输入变量。
5. **测试模型决策变量数量**：L2 需要 3 个决策变量，L3 需要 5 个，以覆盖不同复杂度的测试场景。

---

## 决策

### 1. InputEvents 初始化逻辑修复

**废弃** `skipInputInitRef`（全局布尔 ref，只看"是否有保存"，不看"保存的是哪个模型"）。

**新逻辑**（`useEffect` 内部）：
```js
const restoreFromSaved = isInitialMount.current &&
  selectedModel.key === savedKeyForRestore &&  // 保存的是同一模型
  (readSP()?.inputEvents?.length ?? 0) > 0;
isInitialMount.current = false;

if (restoreFromSaved) {
  // 同模型、第一次挂载：保留 localStorage，下面仍应用 optimizer flags
} else {
  // 新模型或后续加载：重新从 YAML 初始化
  setInputEvents(newInputEvents);
}
```

**关键变化**：
- 切换到不同模型：总是重新初始化（不再用旧模型的 events）
- 刷新页面回到同一模型：从 localStorage 恢复（保留用户改动）
- `savedKeyForRestore` 在组件挂载时一次性读取，不依赖 ref

### 2. optimizer.inputs 标志总是应用

去掉 `freshInputInit` 门控，改为 **unconditionally** 应用：
```js
// 原：if (freshInputInit && Array.isArray(optBlock.inputs))
// 新：
if (Array.isArray(optBlock.inputs)) {
  setInputEvents(prev => prev.map(ev => {
    const inp = withOpt.find(e => e.variable === ev.variable);
    if (!inp) return ev;
    return { ...ev, optimizeValue: true, valueBounds: [...] };
  }));
}
```

即使从 localStorage 恢复，也会更新 optimize 标志（保证 YAML 更改反映到 UI）。

### 3. isLocked 恢复为两种模式统一要求

```js
// 旧（仅 sim 模式需要 lock）：
disabled={mode === 'opt' ? optRunning : (!isLocked || status === 'completed')}

// 新（两种模式都要求 lock）：
disabled={!isLocked || (mode === 'opt' ? optRunning : status === 'completed')}
```

Lock 按钮是安全检查点（validate + lock），在 opt 模式下同样应该先验证模型再运行。

### 4. 模式感知 inputs 显示

`renderInputsContent()` 根据 `mode` 过滤显示的事件：
```js
const optVars = new Set(optimizer.inputs.filter(e => e.optimize?.value).map(e => e.variable));
const visibleEvents = mode === 'opt' && optVars.size > 0
  ? inputEvents.filter(ev => optVars.has(ev.variable))
  : inputEvents;
```

- **opt 模式**：只显示 YAML `optimizer.inputs` 中定义为决策变量的那些（帮助用户聚焦优化空间）。
- **sim 模式**：显示所有 inputEvents（用于手动设置仿真初始条件）。
- 空状态提示改为 mode-aware：opt 模式提示"检查 YAML optimizer.inputs 块"。

### 5. 测试模型重构（L2 → 3 变量，L3 → 5 变量）

| 模型 | 决策变量数 | 场景 | 预估时间 |
|------|-----------|------|---------|
| L1 `l1_drug_single_obj` | **1** | 单日剂量最优化，单目标 | < 1分钟 |
| L2 `l2_drug_pareto` | **3** | 早/中/晚三次给药时段分配，双目标 Pareto | 1–3分钟 |
| L3 `l3_two_drug_mc` | **5** | 工作日五天各自剂量（Mon–Fri），双目标+MC | 3–8分钟 |

L2 变量：`morning_dose`(08:00) / `noon_dose`(12:00) / `evening_dose`(20:00)，吸收率依次递减（70%/55%/45%）。

L3 变量：`mon_dose`–`fri_dose`（工作日各天 08:00），MC 启用（`clearance_rate ~ normal(0.30, 0.04)`，sim_runs=2）。
