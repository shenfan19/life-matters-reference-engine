# 0025 — StoryEditor 转换器四标签平铺布局

**状态**: ✅ 已实施  
**日期**: 2026-04-13  
**作者**: shenfan19

---

## 背景

`StoryEditor` 中间栏原有两个模式：「转换器」和「卡牌构建器」，通过顶部 `Segmented` 切换。随着转换器功能增加，单一转换器页面承载了三类性质不同的配置：

1. **变量映射**——核心转换逻辑，变量角色分配与方程类型设定
2. **结局设计**——原先混入转换器的简单胜负条件（单条件 threshold）
3. **通用卡牌**——独立于模型转换、适用于任意场景的通用机制牌

三类内容共存于一屏，滚动长度过大，且结局设计仅支持单条件，无法表达「变量 A 高 AND 变量 B 低」等组合结局。

## 决策

将中间栏改为**四标签平铺**，取消原先的二级 Segmented 嵌套：

| 标签 | 内容 | 原位置 |
|------|------|--------|
| 变量映射 | Scenario 摘要 + Game Story 预览 + 字段映射 + 自动生成 | 原「转换器」 |
| 结局触发 | 多结局 × 多条件 AND/OR 组合设计器 | 新增（替代旧单条件列表）|
| 通用卡牌 | 预置通用牌库，按类选用 | 新增 |
| 卡牌构建器 | 已生成的场景专属卡牌编辑 | 原「卡牌构建器」 |

## 结局触发设计器（替代旧胜负条件）

旧设计：每条结局 = 一个 `(变量, 运算符, 阈值, WIN/LOSE)` 行。

新设计：每个结局是一张卡片，包含：
- **类型**：WIN / LOSE / 特殊
- **名称**：自定义文本
- **优先级**：数字越小越先检查，支持多结局同时启用时的触发顺序
- **逻辑模式**：AND / OR（点击切换），控制同一结局内多条件的组合方式
- **条件列表**：任意数量的 `(IF/AND/OR · 变量 · 运算符 · 阈值)` 行，可增删
- **描述文本**：结局触发时显示给玩家的信息

加载 Scenario 时自动从 `state` 变量生成默认结局集合（首个优化目标为 WIN 条件，其余 state 变量各生成一个 LOSE 条件）。

## 通用卡牌库

预置 14 张通用牌，分四类：

| 类别 | 代表牌 |
|------|--------|
| 恢复 | 急救包、全面修复、稳定剂 |
| 资源 | 深度调查、紧急调配、战略储备、市场情报 |
| 控制 | 干预措施、临时冻结、转移注意 |
| 特效 | 破釜沉舟、转危为机、连锁反应、深度洞察 |

点击选中/取消，选中状态随导出请求一并传入后端。卡片只显示名称和效果文本（绿色），不显示 AP 费用（游戏中无此概念）和灰色描述。

## 被否定的方案

- **保留二级 Segmented**：顶层「转换器/卡牌构建器」+ 转换器内再嵌三个子标签。多一层认知成本，且视觉上两排控件重叠显得杂乱。
- **单页滚动**：所有内容纵向堆叠。内容过长，不同阶段的配置任务（映射 → 结局 → 卡牌）缺乏分隔。
- **弹出抽屉**：结局设计和通用卡牌用抽屉展示。上下文切换成本高，不适合需要对照 Scenario 数据进行配置的场景。
