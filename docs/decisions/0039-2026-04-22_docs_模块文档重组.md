# ADR 0039 — docs 模块文档重组：modules/ 合并入 design/
**日期**：2026-04-22  
**状态**：已实施

---

## 背景

`docs/` 下存在两个并列的内容层：
- `design/`：按 `{模块}_需求 / 设计 / 实现` 三段式组织，覆盖 sim / game / converter / mod 四个模块。
- `modules/`：5 个横跨模块边界的说明文件（c_sim_model、optimizer、loader、player、c_converter_story），定位模糊，与 `design/` 存在重复和冲突。

具体问题：
- 变量类型（state/input/parameter）定义在 `modules/c_sim_model.md` 而非 `design/c_sim_设计.md`，搜索路径不直觉。
- `modules/player.md` 同时描述仿真引擎和游戏引擎，跨模块混合。
- `modules/optimizer.md` 的优化方法与 `design/c_sim_实现.md` 中的优化插件描述分离。
- `modules/c_converter_story.md` 包含旧目录格式（`mods/core/`）已被新格式（`mods/models/`）替代的内容。
- `modules/loader.md` 的 Loader 实现描述没有对应的 `design/c_sim_实现.md` 章节。

---

## 决策

**删除 `docs/modules/` 整个目录，所有内容按性质归入对应模块的 需求/设计/实现 文件。**

---

## 合并明细

| 原文件 | 内容性质 | 合并目标 |
|--------|---------|---------|
| `modules/c_sim_model.md` | Sim YAML Schema 设计规范 | `design/c_sim_设计.md` § YAML 建模规范 |
| `modules/optimizer.md` | 优化目标与方法选型 | `design/c_sim_设计.md` § 优化目标与方法 |
| `modules/loader.md` | Loader 引擎实现 | `design/c_sim_实现.md` § Loader 模块 |
| `modules/player.md`（sim 部分） | 仿真引擎线程/公式/校验 | `design/c_sim_实现.md` § 仿真引擎运行时 |
| `modules/player.md`（game 部分） | 游戏引擎出牌结算 | `design/c_game_实现.md` § 游戏引擎运行时 |
| `modules/c_converter_story.md` | Story 层架构约束与 Patch 机制 | `design/c_converter_设计.md` § Story 层设计规范 |

**丢弃内容**：`c_converter_story.md` 中使用旧目录结构（`mods/core/`）的示例，以及已在 `c_converter_设计.md` 和 `c_game_实现.md` 中重复的卡牌 YAML 格式说明。

**修复**：`c_game_实现.md` 底部指向不存在文件 `game_and_converter.md` 的死链，改为 `c_converter_设计.md`。

---

## 结果

`docs/design/` 下每个模块均有完整的三段式文档：

```
design/
  c_sim_需求.md      c_sim_设计.md      c_sim_实现.md
  c_game_需求.md     c_game_设计.md     c_game_实现.md
  c_converter_需求.md  c_converter_设计.md  c_converter_实现.md
  c_mod_需求.md      c_mod_设计.md      c_mod_实现.md
  global_prompt.md   (跨模块 UI/UX 规范)
```

无横跨多个模块的孤立说明文件，无死链。
