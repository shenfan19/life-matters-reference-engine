# ADR 0047 — 后端健康检查端点修正 & Loader 缓存键一致性修复
**日期**：2026-05-02  
**状态**：已实施

---

## 背景

两个独立 bug 导致 GUI 频繁显示「Backend offline」并且模型加载变慢：

1. **健康检查打错端点**：`App.tsx` 每 12 秒向 `/api/plugins` 发心跳请求。该端点内部调用 `plugin_manager.scan_plugins()` 扫描文件系统，耗时不定。超过 2500 ms 超时即判为 offline，造成误报。

2. **Loader 缓存键不一致**：`LoaderEngine.fetch()` 第一步用 `(model_name, folder)` tuple 检查缓存，但实际写入缓存时用 `os.path.abspath(file_path)` 字符串。两种 key 类型永远不匹配，导致第一步 cache miss 后每次都调用 `find_model_file()`（可能触发 `os.walk` 全目录遍历），即使模型已在缓存里。

---

## 决策

### 决策一：前端改用 `/api/health` 做心跳

| 项目 | 改前 | 改后 |
|------|------|------|
| 端点 | `/api/plugins?v=...` | `/api/health?v=...` |
| 超时 | 2500 ms | 5000 ms |
| 端点行为 | 调 scan_plugins()，O(n) 文件系统操作 | 只返回组件状态字典，O(1) |

`/api/health` 返回：
```json
{
  "status": "healthy",
  "components": {
    "plugin_manager": true,
    "loader_engine": true
  },
  "plugins_loaded": 0,
  "models_directory": "...",
  "models_exists": true
}
```

### 决策二：fetch() 写缓存时同时写两种 key

```python
# loader_engine.py fetch()
self.models_cache[abs_path_key] = model        # 原有：字符串 key
self.models_cache[(model_name, folder or "")] = model  # 新增：tuple key
```

第一次加载后，后续请求命中第一步 tuple cache，完全跳过 `find_model_file()` 调用。

---

## 结果

```
sim_gui/src/App.tsx
  健康检查 URL: /api/plugins → /api/health
  超时: 2500 → 5000 ms

sim_engine/src/loader_engine.py
  fetch() 写缓存时额外写 (model_name, folder) tuple key
```

---

## 代价与风险

- **健康检查**：`/api/health` 不验证 loader 是否真能读取模型，只检查实例是否为 None。这是合理的：深度检查太慢，浅检查已足够判断 backend 是否存活。
- **双 key 缓存**：缓存大小翻倍（每个模型两个 key）。模型数量少（< 500），内存影响可忽略。
- **缓存清除**：`loader_engine.models_cache.clear()` 仍有效，同时清除两种 key。
