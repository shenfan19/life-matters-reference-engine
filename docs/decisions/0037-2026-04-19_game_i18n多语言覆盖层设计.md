# 游戏故事多语言覆盖层设计（ADR）
**日期**：2026-04-19  
**状态**：已实现  
**涉及文件**：`game/src/core/storyI18n.ts`、`game/src/core/newFormatLoader.ts`、`game/src/components/CardGame.tsx`、`mods/stories/social/ad1666_uk_issac_newton/`、`mods/stories/social/ad1910_po_marie_curie/`、`plugins/preprocessors/story_converter/backend.py`

---

## 核心命题

> **每个故事文件夹内放置 `i18n/{lang}.yaml` 覆盖文件；基础语言保留在原始 YAML 中，覆盖层只包含需要翻译的展示文本；语言切换实时生效，不重置游戏状态。**

---

## 设计决策

### 1. 每故事目录结构

```
mods/stories/social/ad1666_uk_issac_newton/
├── game_story.yaml          ← 基础语言（zh-CN），含 meta.languages: [zh-CN, en]
├── cards/
│   └── player_*.yaml / env_*.yaml
└── i18n/
    └── en.yaml              ← 英文覆盖层
```

覆盖层只放**展示文本**（name、description、flavor、science、variable label、win/lose message），数值与游戏逻辑永远读基础文件。

---

### 2. `meta.languages` 与 `meta.base_language`

| 字段 | 含义 | 默认值 |
|---|---|---|
| `meta.languages` | 声明该故事可用的语言列表 | `[baseLang]` |
| `meta.base_language` | 原始文件的语言 | `"zh-CN"`（手工故事）/ `"en"`（Converter 生成）|

UI 语言选择器只展示 `meta.languages` 中声明的选项，不再硬编码 EN / CHS / CHT 三选一。

---

### 3. 覆盖层 Schema（`StoryI18nOverlay`）

```yaml
meta:
  name: "..."
  description: "..."
  science_note: "..."

variable_display:
  health: { label: "Health" }
  fatigue: { label: "Mental Fatigue" }

win_conditions:
  - message: "【Grade S】..."   # 按 endings 中 win 的顺序索引
  - message: "【Grade A】..."

lose_conditions:
  - message: "【Grade D】..."   # 按 endings 中 lose 的顺序索引

cards:
  player_rest:
    name: "Rest at the Manor"
    flavor: "Sometimes the best thinking..."
  env_plague:
    name: "The Great Plague"
    description: "..."
    science: "..."
```

卡牌按 `id` 匹配；复制牌（`rest_1`, `rest_2`）先精确匹配，再退回 baseId（去掉 `_\d+` 后缀）。

---

### 4. 加载流程

```
fetchYaml(game_story.yaml)
  → loadNewFormatStory(clean, rawContent, lang)
      → 组装 assembled（基础语言）
      → loadI18nOverlay(storyDir, lang, baseLang)   // 若 lang == baseLang 返回 null
      → applyI18nOverlay(assembled, overlay, playerCards, envCards)   // 原地 mutate
      → return assembled
```

`loadNewFormatStory` 新增 `lang` 参数（默认 `'zh-CN'`），原始 YAML 内容由调用方传入，避免重复 fetch。

---

### 5. 实时语言切换

语言切换时**不重置游戏状态**：

1. 调用方（CardGame）缓存 `rawContentRef`（首次 fetch 的解析结果）和 `cleanPathRef`。
2. `language` 变化时，用缓存内容重新调用 `loadNewFormatStory(…, newLang)`。
3. 用新 story 的 `player_cards` / `environment_cards` 建立 `id → card` 查找表。
4. 原地替换所有持有卡牌对象的 state：`hand`、`playerDeck`、`playerDiscard`、`board.card`、`playedCards`、`stagedDiscards`、`envEventDeck`、`envEventDiscard`、`envRevealed.card`。
5. `gs`、`turn`、`playsLeft` 等游戏数值状态**完全不受影响**。

---

### 6. Converter 生成策略

Converter 生成的故事以英文为基础语言（`base_language: en`，`languages: [en]`）。同时生成 `i18n/zh-CN.yaml.template` 作为中文翻译骨架，供后续手工填写或 AI 辅助翻译。

---

## 弃用方案

**方案 A：通用翻译字典**：维护一个全局 `strings.yaml`，所有故事共用。→ 卡牌专有名词（如"苹果树下沉思"）无法精准翻译，放弃。

**方案 B：故事只保留英文，中文用通用翻译**：→ 手工故事的中文是原始语言，丢弃原始语言质量不合理，放弃。

**方案 C：`game_story.{lang}.yaml`（旧 legacy 方案）**：深合并整个对象，数值字段需额外保护，已弃用。新方案的覆盖层只含展示文本，无需保护逻辑值。
