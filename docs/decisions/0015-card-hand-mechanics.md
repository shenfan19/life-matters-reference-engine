# 0015 — 卡牌手牌机制：无回收 + 双重惩罚 + 永久牌

**状态**：✅ 已实施（双重惩罚开关待实现）  
**日期**：2026-04-05

## 背景

需要确定三个相互关联的卡牌机制：
1. **牌组耗尽后是否回收弃牌堆？**
2. **手牌超量的惩罚策略是什么？**（炉石式爆牌 vs 三国杀式回合末弃牌）
3. **是否有永久牌？**（一旦获得每回合可无限使用，不进入牌组循环）

## 决策

### 1. 玩家牌组不回收

每张卡牌在 YAML 中声明的数量经概率计算得出，是有限且经过设计的。牌组耗尽是游戏的自然终态，不触发洗牌循环。

```typescript
// endTurn — 移除了以下自动洗牌逻辑：
// if (plyDeck.length < DRAW_PER_TURN && plyDiscard.length > 0) {
//   plyDeck = shuffle([...plyDeck, ...plyDiscard]);
//   ...
// }
```

环境事件牌组仍保留回收（因为环境事件是循环的自然现象）。

### 2. 双重手牌惩罚（炉石 + 三国杀）

两种惩罚并存，后期可通过 flag 选择性关闭：

| 惩罚 | 触发时机 | 行为 |
|------|----------|------|
| **炉石式爆牌** | 手牌已满时摸牌 | 新摸到的牌直接燃烧（丢弃，不入手） |
| **三国杀式弃牌** | 回合结束时 | 超出手牌上限的牌强制弃入弃牌堆 |

两者产生不同的策略压力：爆牌让玩家珍视每一格手牌空间；回合末弃牌迫使玩家在回合内打出足够的牌。

> 实现状态：逻辑框架已确定，具体 SGS 弃牌 UI 交互待后续实现。

### 3. 永久牌（Permanent Cards）

YAML 中以 `permanent: true` 标记的卡牌具有以下特性：

**初始化**
- 永久牌不进入洗牌堆，游戏开始时直接放入手牌
- 不计入牌组总数（`playerDeckTotal` 仅统计普通牌）

**出牌**
- 效果正常触发，AP 正常消耗
- 卡牌**留在手牌中**，不进入已打出区域或弃牌堆
- 可以每回合重复使用（受 AP 限制）

**手牌计数**
- 永久牌不占用手牌格位（`hand_size` 限制仅约束普通牌数量）
- "手牌已满"提示和每回合摸牌空间计算均排除永久牌

```typescript
// 手牌空间计算
const regularHandCount = curHand.filter(c => !c.permanent).length;
const space = story.game.hand_size - regularHandCount;
```

**视觉标识**
- 卡牌使用主题色（绿色）边框，替代类型色边框
- 右下角显示 ∞ 角标（18px 圆形绿色底）

**典型用例**：科研能力（居里夫人每回合可研究，不需要抽卡）；基础生存技能（永远可用但有 AP 代价）。与之对比，有限资源（香烟、血清、选举资金）仍使用普通牌，数量有限、用完即止。

## 后果

- ✅ 牌组有限性增强了资源管理策略，每张牌的使用决策更有重量
- ✅ 永久牌解决了"基础行动不需要靠运气抽到"的体验问题
- ✅ 双重惩罚两种压力维度正交，玩家需同时管理手牌格位和使用节奏
- ⚠️ 永久牌若效果过强（AP 低、收益高），每回合必用会导致决策平庸化，需通过数值控制
- ⚠️ SGS 弃牌交互（让玩家选择弃哪张）需要额外 UI，当前仅实现框架
