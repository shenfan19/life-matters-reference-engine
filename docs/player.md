# 用户界面 (UI) 和用户体验 (UX) 设计
本文档概述了 `Life Matters` 的 UI/UX 设计原则、主要界面布局和交互模式。

设计原则

* **操作直观性**：确保用户能轻松理解和操作。
* **反馈及时性**：用户操作后提供即时且明确的反馈。
* **数据可视化**：为仿真结果和统计数据提供清晰有效的可视化。

下面给出一个 **“两模块”示例** ——把耗时计算放在 `core.py`，界面放在 `gui.py`。  
特点：

1. **线程隔离**：用 `ThreadPoolExecutor` 把长时间积分运算丢到后台线程，UI 不被阻塞。
2. **实时通信**：后台线程通过 `progress_cb`→ `page.pubsub.broadcast(...)` 把进度 / 中间结果推送回主线程；UI 端用 `page.on_pubsub_message` 接收并刷新控件。
3. **随时可扩展**：想做暂停 / 取消时，只要多传一个 `threading.Event` 或 `Queue` 就行。

## 拓展思路

| 需求           | 做法（核心要点）                                                                                                                                 |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------- |
| **暂停 / 取消**  | 传一个 `threading.Event`（或 `queue.SimpleQueue`）给 `core.integrate`；在循环里 `event.is_set()` 时提前返回。UI 里加 “暂停 / 继续 / 取消” 按钮，按钮点击时 set / clear 事件。 |
| **多任务并行**    | 把 `max_workers` 设大一点，并为每个任务生成唯一 `task_id`，广播消息里带 `task_id` 用于区分。                                                                         |
| **实时曲线**     | 在 UI 里多放一条 `ft.LineChart` 或通过 `ft.canvas` 自绘；收到进度后追加点并 `page.update()`。                                                                  |
| **输入参数随时修改** | 计算线程启动前取一次当前参数；如果想“实时调整算法参数”，可以把参数改为 `multiprocessing.Value`/`Queue`，让核心随时读取。                                                            |

这样就把 **“Flet UI ⇄ 计算内核”** 的数据流和线程模型搭建好了，你可以直接换上自己的积分或仿真代码。如果还想加别的功能，告诉我就行！
