# MOD 需求

## 核心定位

MOD 系统是 LM-Game 的内容扩展层。官方只维护最严谨的基石场景；社区创作者通过 MOD 扩展角色、场景和故事包。

**原则**：官方搭框架，社区填内容；官方不干涉 MOD 内容立场，以科研框架为边界。

## 功能需求

### 场景 MOD
- 用户可创作新的历史场景（新的 `mods/stories/{category}/{id}/`）
- 场景需符合 game_story.yaml 格式规范（见 `game_impl.md`）
- 支持自定义角色、卡牌、初始参数

### 内容分级
- MOD 须标注内容分级（年龄限制）和触发警告（暴力/死亡/歧视主题）
- 官方场景同样须遵守此规范

### 社区治理需求
- 用户可上传 MOD，平台不预审
- 举报机制：24小时内响应明显违法内容
- MOD 创作者须承担其内容的法律责任

### 角色邀请机制
- 开放用户写信邀请设计新官方角色（非开放全员提交）
- 设计摩擦成本：筛出真正有热情的人，每封信都是潜在社群故事

## 安全边界

- 以项目为重，以医学为重，官方不主动碰敏感话题
- 社会学 MOD 开放：用户可添加不同民族、政治观点的内容
- LM 官方：不干涉、不支持、不宣传，以科研框架为本
- 防火墙原则：保持"框架是教育而非批判，数据是历史而非政治"，避免成为代理战场

## 建模数据规范 (Data Standards)

### 变量与公式文档规范

为了保证仿真模型的可信度与可维护性，所有 YAML 中的变量定义（variables）和公式（formulas）必须遵循以下强制规范：

1. **强制 `description`**：必须提供简洁的中文描述，说明该变量或公式的物理/医学意义。
2. **强制 `reference`**：所有数值（value）、范围（bounds）和动力学公式（dynamics）必须标注数据来源。
   - **格式多样性**：`reference` 既可以是单个字符串，也可以是 YAML 列表（List），用于引用多篇文献。
   - **可追溯原则**：不强制要求标准的 BibTeX 格式，但必须包含足够信息（如 DOI、PMID、简写引用或 URL），让其他人能在 30 秒内定位到原始文献。
   - **缺失来源占位符**：若数据来源暂时缺失，必须填写 `["TODO:SOURCE"]` 并在 `comments` 中注明估算逻辑，以便后续核查。
3. **可选 `comments`（或 `notes`）**：用于记录建模决策逻辑。
   - **用途**：当多个文献数据冲突时，说明为什么选择了某一个；或者记录该参数的微调过程。
   - **位置**：应独立于 `description` 和 `reference` 字段，确保语义清晰，且不干扰 UI 显示。
