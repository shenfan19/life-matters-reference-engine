# LifeMatters 仿真器界面设计方案纪要

**日期**：2026-04-01  
**版本**：v0.4.x  
**状态**：已实施（布局重构）

---

## 一、背景与问题

LifeMatters 仿真器（Simulator）是一个面向科研验证和教育展示的参数化仿真工具。用户通过选择场景模型、设置输入变量和优化参数，运行仿真并观察结果。

### 旧版布局的问题

旧版采用**三列固定布局**：

```
左侧(300px) | 中央(flex) | 右侧(280px)
场景树+详情  | 单图canvas  | Tabs: 输入|变量|公式|计划
```

经使用分析，存在以下核心矛盾：

1. **图表 vs 参数空间竞争**：单一 canvas 把所有变量叠加在一张图上，量纲不同的变量无法清晰比较；右侧 Tab 折叠了大量控制信息。

2. **输入和优化器空间严重不足**：
   - 输入变量展示方式（小卡片）无法直观编辑
   - 优化器配置（变量范围、目标、约束、算法超参）需要较大界面空间，但被压缩在一个 280px 宽的 Tab 里

3. **字体缩放破坏布局**：全局 `zoom: fontSize/16` 会使固定像素区域随字体变化收缩或膨胀，三列布局在字体放大时特别拥挤

4. **可验证性差**：图表无坐标轴标尺、无悬停数值、无单变量导出，难以做精确校验

---

## 二、设计目标

经过多轮讨论，明确以下优先级排序：

> **输入/优化参数 > 图表展示 > 场景导航**

理由：
- 这是一个**参数驱动型**工具，核心工作流是"配置参数 → 运行 → 观察结果 → 调整参数"
- 图表是结果展示，可以导出、可以只选部分变量，灵活度高
- 优化器配置是最复杂的操作，需要充足空间（变量范围 × N + 目标 + 约束 + 算法）

## 三、新版布局方案

### 整体结构

```
┌──LEFT (380px, 可拖 200–520px)──┬──CENTER (flex, 全宽图表)──┐
│                                 │                            │
│  ┌─场景树区 (140px, 可调高)────┐│ [工具栏: 运行/暂停/导出]  │
│  │ 搜索过滤 + 文件树           ││                            │
│  │ 选中场景 + 验证/锁定按钮    ││ variable_1 (单位)   [↓CSV]│
│  └─────────────────────────────┘│ Y轴─ ─ ─ ─ ─              │
│  [↕ 拖拉分隔线]                 │      ╱╲___               │
│  ┌─控制台 (flex, 可滚动)───────┐│   0 ─────────── 24h      │
│  │ Tabs: 输入|变量|公式|计划   ││                            │
│  │       优化器                ││ variable_2 (单位)   [↓CSV]│
│  │─────────────────────────────││ ...                        │
│  │ [Tab 内容 - 充足空间]       ││ (每图独立Y轴+X轴+gridline)│
│  └─────────────────────────────┘│                            │
└─────────────────────────────────┴────────────────────────────┘
```

### 关键决策

#### 1. 取消右侧面板，全并入左侧 Tab

**为什么**：右侧 280px 对复杂的优化器 UI 不够用；左侧有弹性宽度（可拖到 500px+）。合并后减少一个分隔轴，图表横向空间增大约 30%。

#### 2. 左侧面板上下分区

- **上区（场景树，默认 140px）**：只放场景选择和锁定功能，不和控制台抢高度
- **下区（控制台，flex）**：全部交互操作，独立滚动

**为什么**：场景选定后很少频繁切换，控制台才是高频操作区。用户有时需要同时看到当前场景信息和输入参数，上下分区可以同时可见。

#### 3. 多图替代单图

每个 output variable 独立一张图，包含：
- 独立 Y 轴（自动计算 nice tick，带单位）
- 共用 X 轴（时间，小时）
- 水平/垂直网格线
- 鼠标悬停：竖向准星 + 数值提示
- 独立 CSV 导出按钮

**为什么**：不同变量量纲完全不同（能量 0-100、血糖 70-600、药物剂量 0-20），叠加在同一 Y 轴意义不大，各自独立坐标更便于精确校验。

#### 4. 左侧宽度默认 380px

从旧版 300px 调整到 380px。原因：
- 输入变量一行需要：变量名 + 当前值 + 编辑框 + 单位，至少 320px
- 优化器一行需要：变量名 + min/max 输入 + 锁定开关，至少 350px

## 四、暂缓的决策

### 场景选择器重构（游戏筛选形式）

**讨论结论**：下一阶段将场景树替换为游戏风格的筛选面板：
- 标签切换按钮：`[全部] [示例] [生理] [疾病] [社会] [游戏场景]`
- 按元数据（type, category, tags）筛选
- 显示平铺卡片列表而非树状结构

**当前保守方案**：保留文件树，等布局稳定后再替换。

**Dropdown 方案（备选）**：若要进一步压缩场景选择空间，可将场景树改为顶部工具栏中的带搜索功能的 dropdown。Ant Design Select 组件支持 `showSearch` + 自定义过滤，但无法实现视觉标签切换（游戏风格），因此暂不优先。

### 仿真/优化/建模 三个独立工作空间

当前用 `mode: 'sim' | 'opt'` 切换，长远考虑拆分为三个一级 Tab：

- **仿真视图**：本方案布局
- **优化视图**：全屏 Pareto 前沿 + 完整优化配置
- **建模视图**（可选）：变量/公式/计划表的结构化编辑

这与 Clash 风格的"主标签 + 详情标签"一致，等优化器功能完善后实施。

## 五、技术实现说明

### 组件结构变化

| 模块 | 旧版 | 新版 |
|------|------|------|
| 图表渲染 | 单一 canvas + 多变量叠加 | `SimChart` 组件，每变量独立 |
| 右侧面板 | `renderRightPanel()` | 删除，内容迁至左侧 Tab |
| 左侧 Tab | 无 | `leftTab` state + `leftTabs` 数组 |
| 左侧宽度 | 300px | 380px (max 520px) |
| 场景树高度 | 占左侧约一半 | 固定 140px，可拖拉 (min 80, max 300) |

### SimChart 组件设计

- 使用 HTML Canvas 绘制（不引入外部图表库，保持轻量）
- Y 轴 nice tick 算法：`range → magnitude → normalized → {1,2,5,10} × magnitude`
- 悬停交互：mousemove → 计算最近数据点 → 绘制竖向虚线 + 显示 tooltip overlay
- 单变量 CSV 导出：`Blob + URL.createObjectURL`，包含 `time_s, time_h, varName` 三列

## 六、待解决问题

1. **输入变量的计划表集成**：目前输入 Tab 和计划 Tab 是分开的，但实际上输入变量的值来自计划表驱动，用户可能需要在同一视图编辑"变量 + 其对应的计划表"
2. **优化结果可视化**：Pareto 前沿展示在当前布局中还是占位符
3. **字体缩放适配**：`zoom: fontSize/16` 会影响 canvas 的实际 CSS 尺寸，需要在 `ResizeObserver` 中重绘
